# Interface Evolution Benchmark v0.1 — Negative Result Ledger

## Status

Frozen with the first executable run: 40 seeds per scenario-agent pair.

This ledger records where interface revision fails, should not occur, or remains theoretically redundant.

---

## 1. Sufficient initial interface

### Condition

The visible cue already identifies the latent target.

### Result

The revision agent did not activate the paid sensor and achieved perfect held-out accuracy.

### Interpretation

A failure-free or solvable interface does not justify interface revision.

This is a successful negative control against interface fetishism.

---

## 2. Useless sensor

### Condition

The initial interface is non-identifying, but the candidate sensor is independent of the target.

### Result

The revision agent rejected deployment after bounded probes.

### Interpretation

Recognizing that the current interface is insufficient does not imply that any additional distinction deserves authority.

---

## 3. Informative but uneconomic sensor

### Condition

The sensor predicts the latent regime but its cost exceeds its expected advantage over the best fixed-interface action.

### Result

The revision agent rejected deployment.

### Interpretation

More information is not automatically a better operational interface.

Interface value is target-, cost-, and policy-relative.

---

## 4. Spurious training cue

### Condition

The initial cue is strongly predictive during training but becomes uninformative during held-out evaluation.

### Result

The revision agent did not acquire the sensor during training and fell to chance-level evaluation performance.

### Interpretation

v0.1 revises only after experienced contradiction.

It cannot anticipate an interface failure hidden by a training-only correlation.

This is a real limitation, not a passed capability.

A stronger system would need prospective stress testing, distribution-shift models, or deliberate interface challenge before deployment.

---

## 5. Active-sensing / POMDP redundancy

### Condition

The candidate sensor, its cost, and the target variable are predeclared.

### Result

The observed behavior is fully describable as costly feature acquisition or active sensing in a partially observable decision problem.

### Interpretation

The run does not establish that `interface evolution` is a distinct mechanism or research program.

The framework earns separate authority only if a later benchmark discriminates capabilities not already captured by those formalisms, such as:

- generating a new candidate measurement;
- revising the target decomposition;
- constructing a new variable from interventions;
- changing the question-generating process;
- identifying shared hidden assumptions across all available sensors.

---

## 6. Target authorship remains external

The evaluator defines the latent variable, correct action, sensor, reward, and acquisition cost.

The agent does not determine which distinction matters.

Therefore v0.1 tests interface selection only in the weakest sense: whether to deploy one offered measurement.

---

## 7. Complexity cost is under-modeled

The benchmark charges a scalar sensor cost.

It does not model:

- representational complexity;
- slower learning from larger interfaces;
- new confounding pathways;
- downstream coordination cost;
- maintenance and replacement cost;
- harmful reification of an artificial variable.

A sensor can pass v0.1 while still degrading a richer system.

---

## 8. Transfer evidence is narrow

The acquired sensor retained value under one moderate preregistered prevalence/noise shift.

This does not establish broad transfer reliability.

Severe changes in prevalence, sensor calibration, adversarial manipulation, or reward structure remain untested.

---

## Frozen conclusion

The first run supports only the local diagnostic distinction:

\[
\boxed{
O\text{-insufficiency can dominate additional }M\text{-optimization under a declared collision.}
}
\]

It does not yet support a distinct general theory of interface evolution.

The strongest observed failure is:

\[
\boxed{
\text{No experienced contradiction}
\Rightarrow
\text{no interface challenge in v0.1}.
}
\]
