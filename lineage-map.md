# Lineage Map

## Purpose

The repositories are best read as a sequence of changing research objects rather than as independent finished theories.

The overall movement is:

\[
\boxed{
\text{computational reach}
\rightarrow
\text{representation change}
\rightarrow
\text{recursive adaptation}
\rightarrow
\text{causal correction}
\rightarrow
\text{authority revision}
\rightarrow
\text{evidential governance}
}
\]

This map records conceptual ancestry. It does not merge the evidential status of the repositories.

---

# Phase I — Interfaces and computational reach

## interface-induced-computational-geometry

Core move:

\[
\mathcal C(\rho,T)\leq A
\]

A task is not intrinsically reachable or unreachable. Reachability depends on the relation among task, interface, architecture, execution, and resources.

Primary contribution:

\[
\text{difficulty}
\rightarrow
\text{task--interface--architecture relation}.
\]

---

## computational-leverage

Introduces counterfactual reach expansion under a bounded resource budget.

Core orientation:

\[
\Phi(v\mid B)
=
\mu_w(R(B,v))-
\mu_w(R(B)).
\]

The relevant question becomes not merely whether a tool improves one output, but how much reachable possibility it adds.

---

## computational-phase-boundary

Proposes the causal sequence:

\[
\Delta\Lambda_E
\rightarrow
\Delta\alpha
\rightarrow
\Delta C.
\]

Search-efficiency improvement is separated from design-space expansion and later capability acceleration.

Adversarial resource-scaling tests exposed the fragility of that ordering under resource confounding.

# Phase V — Experimental mechanism attempts

## ctre-simulator

Attempts to compare fixed-basis adaptation with representation adaptation under regime change.

Important execution defects currently prevent the intended claim:

- returned next-state values are discarded;
- transfer evaluation ends before the configured shift;
- the range variable is unused;
- one return type conflicts with evaluator expectations;
- fixed variables make the intended multiplicative structure unidentifiable.

The design intent remains useful; the existing execution does not validate autonomous representation discovery.

# Phase VI — Authority, inheritance, and controlled revision

## adaptive-inheritance

Treats empirical contradiction as a reason for mechanisms to lose operational authority.

It separates acknowledgment from causal authority transfer.

The current implementation depends on externally supplied attribution and admissibility.

---

## rahu-benchmark

Attempts to measure authority revision, adaptive depth, and correction stability.

A critical defect is that the task itself supplies authority-change telemetry; the same reported change appears even for a static system.

The benchmark therefore validates arithmetic and telemetry flow, not autonomous corrigibility.

# Phase VII — Interface Theory and evidential governance

## interface-theory

Changes the research form.

Rather than proposing another broad adaptive quantity, it asks whether a declared target is identifiable through a declared interface over a declared class:

\[
L=\widehat L\circ O.
\]

Its no-bypass hierarchy is:

\[
\text{factorization}
\rightarrow
\text{estimation}
\rightarrow
\text{predictive validity}
\rightarrow
\text{causal intervention}.
\]

It contains frozen, class-scoped Gate 1 results and explicit interpretation limits.

Gates 2–4 remain closed.

It does not establish a universal correctability metric, a superior adaptive architecture, or open-ended recursive improvement.

# Phase VIII — The Correctable Lineage

## the-correctable-lineage

This repository does not add a new validated mechanism.

It records the shape of the corpus as a whole.

Its object is:

\[
\boxed{
\text{a traceable lineage in which contradiction can improve future adaptive machinery without erasing what remained valid}
}
\]

Its function is synthesis, orientation, scope preservation, and historical continuity.

It does not supersede the canonical records of the underlying repositories.

# The recurring transformation

Across the phases, contradiction repeatedly moves the research object upstream:

\[
\text{output failure}
\rightarrow
\text{interface failure}
\rightarrow
\text{representation failure}
\rightarrow
\text{generator failure}
\rightarrow
\text{selection failure}
\rightarrow
\text{authority failure}
\rightarrow
\text{measurement failure}
\rightarrow
\text{governance revision}.
\]

The deepest stable operation is:

\[
\boxed{
\text{contradiction}
\rightarrow
\text{discover hidden conflation}
\rightarrow
\text{refactor the causal object}
\rightarrow
\text{retest each component separately}
}
\]

That operation, rather than any single equation, is what gives the corpus developmental unity.
